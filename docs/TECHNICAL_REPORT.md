## 摘要

本项目面向受限黑盒大模型驱动的科学研究任务，解决三类相互关联的问题：模型会把形式自洽误当科学正确，工具执行成功会被误当假设成立，多轮反思会把早期错误持续注入后续上下文。系统以“契约与证据驱动的推理期自改进”（Contract- and Evidence-Driven Test-Time Self-Improvement，CET-SI）为理论中心，将大模型限定为候选假设与解释的提议者，由外层确定性控制层管理目标契约、调用预算、版本化产物、独立验收和终态交付。

系统保留原数学仓库既有的 `user_agent.ReasoningAgent(client=...).solve(problem, metadata)` 兼容接口及 M1—M5、R0/R2、S1—S3 机制，同时向动力学控制、热物理数值实验、实验数据分析和材料扩展示例提供统一 ScenarioPlugin / DomainAdapter / ScenarioRegistry 边界。该兼容接口不是 Track 160 强制入口。四个基础场景与第五场景共享同一注册和调度语义，不把场景名单硬编码为全部就绪，也不把测试声明直接当成生产证据。

本报告沿用原仓库技术报告的“一中心两基本点、三大执行模块、三大支撑机制”主线，并按当前源码重写工程映射。原报告中的“WASI 全环境可用”“100% 合规”“固定精度增益”等结论不在本文复述，除非存在当前版本的可复验证据。

**关键词**：推理期自改进；目标契约；证据门控；Agentic MoE；递归自改进；独立验收；科学多智能体

## 1. 一中心两基本点：理论与技术顶层设计

### 1.1 一个中心：契约与证据驱动的推理期自改进

在冻结黑盒模型和有限调用预算条件下，系统不能依靠更新模型参数消除推理错误，也不能把多次自我肯定累积成数学或科学证明。Track 160 的 harness 与技术组合可按项目需要选择；本文不把原数学材料的 `stream=False`、`n=1`、单题 1200 秒或全场 6 小时约束迁移为本赛题规则。CET-SI 将改进过程限制在单题或单课题的可审计执行周期内：

1. 将原始问题编译为显式目标、作用域和待关闭义务；
2. 模型只提出计划、候选、解释或修复，不直接改变义务状态；
3. 工具只产生带调用身份和作用域的观察，不自动产生科学事实；
4. 独立 validator 或领域检查器核验候选主题、证据范围和验收条件；
5. 修复必须针对具体质疑与未关闭义务，且受根预算和最大修复次数约束；
6. 未决、失败、超时和远端结果未知分别记录，不用“执行完成”冒充“假设成立”。

因此，答案生成与交付裁决是两个正交过程。所有科学候选保持 `candidateVerified=false`；即使最终按限定范围形成可交付候选，也不将其伪标为全局已验证真值。

### 1.2 第一个基本点：双核异构的元认知闭环

系统采用 Python 宿主与 TypeScript 控制层协同的异构结构：

| 层级 | 当前实现 | 核心职责 |
| --- | --- | --- |
| 统一入口与宿主层 | `user_agent.py`、`mathagent/`、`python/astra_web/` | 保持原数学仓库兼容接口；管理公共客户端、Web 请求、持久化和实际环境配置 |
| 契约与调度层 | `packages/agent-kernel/`、`packages/domain-contract/` | 根预算、义务账本、候选门控、任务与产物版本、终态裁决 |
| 场景扩展层 | `packages/scenario-sdk/`、`packages/scenario-catalog/`、`packages/domain-*` | 场景注册、能力 readiness、DomainAdapter 适配、第五场景扩展 |
| 证据与工具层 | `math_families/`、`mathagent/output_checks/`、领域数值包 | 符号检查、参数估计、有限差分、统计推断和独立 validator |
| 数据与记忆层 | `input_assets.py`、`topic_memory.py`、SQLite 运行存储 | 输入哈希、真实文件边界、课题版本、级联失效、恢复和导出 |

数学原生生产链继续由既有 `user_agent` 调用边界驱动；通用科学场景通过 ScenarioPlugin 注册和模型规划—工具—解释—审查链运行。通用 Kernel 是可复用调度机制，不在文档中冒充已经无损替换数学原生链。

### 1.3 第二个基本点：三项耦合支撑机制

#### 机制一：Agentic MoE 的任务拆解与动态语义路由

系统将复杂任务表示为 WorkUnit 和 Obligation 的依赖关系，而非扁平拼接对话。路由同时考虑场景合同、问题类型、未关闭义务、可用工具和剩余预算。模型可提出新路线或工具动作，但是否派发由控制层校验：

- 静态入口由 ScenarioRegistry 和 DomainAdapter 决定；
- 动态路线必须经 `classifyRoute` 判为实质路线，拒绝同义重复探索；
- 模型工具动作只能命中领域白名单；
- 工作包必须经 `validateWorkPacket` 和 run/task 身份绑定；
- 子任务、修复和跨场景协作共享根预算语义，不能通过递归重置额度。

数学场景继续使用数学算法族、方法卡、A2 Lite 与既有动态路由；通用场景使用统一的规划、工具调用和验收接口，不在 Kernel 中硬编码某一学科的专用分支。

#### 机制二：RSI 记忆净化与图结构局部纠偏

递归自改进的风险不是“没有反思”，而是错误记忆在反思中持续占主导。系统以版本化 Artifact 和依赖 DAG 控制污染范围：

1. 上游产物更新后，下游依赖闭包被标记为 `STALE`；
2. 被客观验证否定的候选从活跃候选中移除，不作为安全回退；
3. 修复必须携带已解决的 Challenge ID，部分修复不能替换受保护父候选；
4. 截断、异常或空修复不产生新候选版本；
5. 课题长期记忆中的上游数据版本变化会触发 `REQUIRES_REVERIFICATION` 和 `INVALIDATED` 级联状态。

该机制把“重新生成全文”改为“定位污染子图并有界修复”，同时保留正确上游证据和失败历史。

#### 机制三：外层元认知判断与多级证据门控

数学原生链保留 R0 预飞、R2 对抗审查和 S1—S3 证据门控，分别处理规划准入、候选挑战、作用域对齐、修复替换和终态交付。

通用 Kernel 与科学场景使用同一原则的另一实现：

- 模型或工具原始输出先形成 Observation；
- 独立 validator 接收 CheckSpec 与 CandidateView；
- validator 回执的 `validatorId` 必须与检查一致；
- `subjectHash` 必须与当前候选内容一致；
- validator 调用计入工具预算，失败或缺失只能保持未决；
- 只有候选存在、全部义务按限定范围闭合且交付投影有效时，Kernel 才返回 `COMPLETED`。

“独立审查”指角色、上下文和职责隔离，不宣称使用了不同模型或不同供应商。同源模型审查仍需要确定性工具和外部证据锚点。

## 2. 三大执行模块：从问题到可信交付

### 2.1 模块一：题目分析与可执行契约编译

输入首先被转换为可追踪的研究契约，而不是直接交给模型自由发挥。

数学原生链执行问题身份绑定、题型识别、义务图编译、R0 预检和初始专家路由。通用科学链执行以下步骤：

1. 根据 `scenarioId` 或 `domainId` 从生产 Registry 获取场景合同；
2. 校验输入文件路径、扩展名、大小和 SHA-256；
3. 检查 solver、模型能力、领域引擎与隔离运行时 readiness；
4. 规划 Agent 仅看到问题、数据摘要、来源哈希和可选文献证据；
5. 规划 Agent 必须返回 `EXECUTE` 或 `ABSTAIN`，且只能申请白名单工具；
6. 不适用、信息不足或输入越界时明确拒绝，不生成替代性实验结果。

生产目录不再硬编码“全部 READY”。缺少 solver 时返回 `SOLVER_NOT_CONFIGURED`；Registry 不可用时目录降级为 `NOT_READY`，而不是保留虚假可用状态。

### 2.2 模块二：受控求解与真实文件驱动

当前随附数据是**合成基准**，但系统消费的是用户可替换的真实文件内容，而不是从题干提取真值后反向制造数据。生产请求支持 `benchmarks/` 与 `uploads/` 两类受限来源。

| 场景 | 实际输入 | 工具执行 | 主要科学义务 |
| --- | --- | --- | --- |
| 数学研究 | 自然语言题面与数学资产 | 原生数学规划、算法族、符号检查 | 定义域、推导、边界、完备性与输出检查 |
| 动力学控制 | 时间、外力、位移 CSV | 数值微分、最小二乘、RK4 前向模拟 | 正物理参数、抗混叠、训练/留出隔离、RMSE、残差白性 |
| 热物理计算 | 时间、空间、温度 CSV | 显式有限差分、网格收敛、初边值模拟 | CFL、二阶收敛、边界一致性、实验末态误差 |
| 数据分析 | 分组变量与数值变量 CSV | Welch t 检验、效应量、置信区间、诊断 | 方法适用性、显著性、效应量、区间与前提诊断 |
| 材料扩展示例 | 场景合同与受信插件配置 | DomainAdapter 和独立 validator | 扩展注册与统一调度语义，不宣称真实 DFT 结果 |

控制估计器不再把负参数静默钳成正值。非正质量、阻尼或刚度会保留在估计结果中，并使物理义务显式失败。热物理将“数值方法收敛验证”和“真实初边值/实验末态对照”分开报告，避免用固定正弦算例替代实验输入。

### 2.3 模块三：闭环验证、修复与终态交付

通用科学场景的标准链为：

```text
规划 Agent
  → 白名单数值工具
  → 解释 Agent
  → 独立审查 Agent
  → 有界修复 Agent（仅在 REQUEST_REPAIR 时）
  → 独立复审
  → 按义务状态交付或保持未决
```

完整修复链最多五次模型调用。审查可返回接受、要求修复、拒绝或证据不足；修复只修改候选解释，不能篡改数值回执。最终响应同时保留数值结果、角色产物、审查结论、文献证据和 `candidateVerified=false`。

## 3. 输入资产、文献与曲线能力及证据边界

### 3.1 输入资产与数据版本

`input_assets.py` 对输入执行路径白名单、路径解析、大小限制、扩展名检查和 SHA-256 记录。执行前再次核验文件大小和哈希，文件在解析后发生变化会返回 `INPUT_ASSET_CHANGED`。

课题档案保存数据版本 ID、数据集引用、SHA-256、记录数是否已知以及状态。相同资产复用同一版本；同一引用出现新哈希时生成新版本，并使依赖旧版本的假设和记忆进入复验或失效状态。

### 3.2 检索与开放原文

可选文献链为：

```text
Semantic Scholar 检索
  → 开放状态与外部 ID 记录
  → HTTPS 开放 PDF 下载
  → PDF SHA-256、页数和逐页文本提取
  → 规划/解释/审查使用证据
  → 报告保留引用与访问疑虑
```

系统区分摘要、开放全文、全文提取为空和访问失败。未开放全文保留 T35 疑虑；PDF 下载或解析失败不会伪写“已阅读原文”。

### 3.3 图像曲线提取

曲线解析器支持显式校准的 RGB 像素轨迹提取。调用者必须提供图像、数据坐标范围、像素绘图区、曲线颜色与颜色容差。系统输出曲线点、摘要统计、质量审计和来源图像哈希；坐标歧义、校准错误、有效点不足或质量审计失败均显式返回。

## 4. 隔离、预算与故障语义

### 4.1 有界执行

根预算覆盖模型调用、工具/validator 调用和 deadline。未发送的本地拒绝与已发送但结果未知分开处理。工具超时、候选截断、无效工作包和非法验收回执均不能推进到完成态。

### 4.2 Worker fail-closed

通用 Python Worker 当前只有在显式资源隔离测试配置下才使用 Windows Job Object 执行，限制 CPU、内存、活动进程数、输入只读和输出大小。Job 初始化或分配失败不会回退宿主 Python。

当前 pywin32 环境没有可验证的网络隔离后端，因此默认执行返回 `ISOLATION_UNAVAILABLE`，健康检查降级。该状态不是完整 WASI 或无网络沙箱验收通过；可选 WASI 资产必须按实际安装路径另行提供和验收。

### 4.3 科学失败与系统失败分离

数值义务未闭合表示当前假设或模型未通过，不伪装成基础设施成功。当前随附控制样本在离线真实文件验收中未闭合留出 RMSE 与残差白性义务，系统保留失败结论；不使用旧摘要中的固定参数、固定 p 值或固定成功率替代本次结果。

## 5. 跨场景协作与课题记忆

### 5.1 有界跨场景委派

协作任务携带父 run、目标场景、输入工件、继承预算和递归深度。系统拒绝自委派、未注册目标、超深度和预算耗尽。

控制到数据分析的旗舰不确定性链使用真实残差序列，执行 Jarque–Bera 正态性检验、Ljung–Box 白性检验、RMSE 和均值置信区间计算。结果由实际残差决定；缺少残差、零方差、非有限值或工具预算不足均明确失败。TS 协作器则通过公共 Kernel 实际执行目标 DomainAdapter，返回真实终态和消耗预算。

### 5.2 课题长期记忆与恢复

每次运行自动归档：

- 原始问题与场景；
- 输入资产版本和 SHA-256；
- 假设 ID 与证据哈希；
- run ID、终态、停止原因和最终报告；
- 记忆复用许可与依赖数据版本。

创建课题是幂等操作，不会在导出时清空已有档案。JSON 原子落盘，支持 SQLite 运行恢复、JSON/Markdown/ZIP 导出和逐文件 SHA-256 验签。T37 级联失效确保上游数据变化后，旧结论不会被当作有效事实复用。

### 6.2 冻结评分与完整分母

评分器按任务类型检查实际数值义务：控制检查物理边界、留出 RMSE、残差、泄露和采样；热物理检查收敛阶、CFL、边界和实验对照；统计检查 Welch 方法、p 值、效应量、区间和前提诊断；数学任务按声明的有限评分范围检查精确答案。

所有任务进入分母，包括未配置、配置不支持、执行失败和评分失败。事实表只呈现实际运行结果，不预设 B2 必须高于 B3，也不在少量任务上宣称统计显著性。

### 6.3 当前证据边界

已使用受控离线模型配合真实 CSV 和数值工具验证各组行为、调用次数、修复与失败路径。该验证证明评测配置确实生效，不等同于真实 Atria 全量正式跑批。旧发布文件中的固定指标不作为本版评测结果；正式 Atria 结果必须另行执行并保留原始运行产物。

## 10. 结论

本系统的技术内核不是“增加更多 Agent 角色”，而是把科学研究生成过程置于可执行的契约、预算和证据边界内。模型负责提出可能性，工具负责产生观察，独立验收负责限定结论，记忆系统负责追踪版本与污染范围，终态机负责拒绝不具证据的交付。

“一中心两基本点”因此落实为可检查的实现：以 CET-SI 为中心，以双核异构闭环为第一基本点，以 Agentic MoE、RSI 局部纠偏和多级证据门控为第二基本点。数学原生链与通用科学场景共享这一原则，但各自的真实接口、验证程度和未闭合事项均被明确保留，不以架构描述替代实证验收。
