# P3 local tool Host profile

The tool-only milestone is recorded below. The current
[method Host increment](P3_METHOD_HOST.md) upgrades P3 peers to
`1.1-p3-host-local` and adds opt-in catalog/load callbacks. Method loading
defaults to off, so the tool examples retain their behaviour. The current
context schema is `p3-action-context-v2`; old P3 wire versions are rejected.
P0/P1/P2 protocols remain unchanged.

This increment connects the P3 TypeScript action loop to a real Python Host
and Node child process. Model responses remain literal offline fixtures.
The only mathematical effects are the two existing isolated operators,
`polynomial_expand_coefficients` and `linear_system_solution_set`.
No production client, network provider, new tool, dependency or default-engine
switch is introduced. The official Python entry and solver remain unchanged.

## Run

Build TypeScript before running Python integration tests or the CLI:

```sh
node node_modules/typescript/bin/tsc -b
PYTHONDONTWRITEBYTECODE=1 python -m python.astra_bridge.p3_host_offline --problem 'Expand (x+1)**2' --action '{"action":"tool","name":"polynomial_expand_coefficients","args":{"expression":"(x+1)**2","variables":["x"],"parameters":[]},"scope":"expand"}' --action '{"action":"final","answer":"x**2+2*x+1","complete":true,"unresolved":[]}'
```

The final text above is supplied by the fixture, not generated by a real model
or independently proved. Successful output is still MOCK_ONLY,
candidateVerified=false, strictAcceptance=NOT_PERFORMED and TARGET_UNVERIFIED.

The Python API is `run_p3_host(problem, receipts=[...], max_model_calls=3,
max_effects=2, timeout=5)`. Each receipt has exactly deliveryStatus and text.
The limits are 0..3 model callbacks, 0..2 tool attempts and at most five seconds.
CLI `--action` can be repeated up to three times and denotes COMPLETE fixture
transport. The API additionally exercises TRUNCATED/ERROR/UNKNOWN. Missing
fixture data yields an ERROR transport receipt, not an unrecorded retry.

## Protocol and ownership

The normative manifest is `packages/protocol/schema/p3-host.schema.json`,
version `1.0-p3-host-local`. It permits only runtime.initialize, session.solve,
session.stop, model.generate and tool.execute, with fixed directions.
This is a distinct opt-in profile: P2 `1.1-p2-host-local`, P0 and P1 remain
compatible with their existing entry points and schemas.

The Node entry injects a P3 codec into the existing P2HostChannel; it adds no
second reader or framing implementation. Python inherits P0's selector pump,
single reader, bounded frames, child environment allowlist and cleanup.
Both sides reuse the P0 strict parser/schema subset. Frames remain limited to
65536 bytes, depth 24 and 64 total frames. Handshake IDs are host-1/2/3;
callbacks are node-model-N and node-effect-N.

The app composition root joins real M1 contract/task state, P2ModelGate,
P3EffectGate and M3 context preparation. Mathematical packages do not import
each other. One candidate-bearing RUNNING task is retained; no fake artifact
or WorkPacket is manufactured from final actions, and no obligation becomes
SAT. Initial M1 compilation is a trusted deployment component, not something
Python independently proves.

Method actions stop with EFFECT_UNAVAILABLE in this Host profile. The
separate [P3 fixture library](P3_FINITE_ACTIONS.md) still supports method cards;
bringing catalog/load callbacks into this profile remains a later increment.

## Host second admission and provenance

Python retains the exact model requests and actual returned fixture receipts.
A tool request must match the latest COMPLETE model action in full, including
scope wording, and carry the exact session/problem/contract/task/scope/source
binding. It must also have the next effect ID, an unused source request,
available quota and time. Tool input is validated again by the original
RegisteredExecutor before its isolated worker is started. Arbitrary generated
code, file paths and additional registered operators are not enabled.

Canonical name/arguments identify repeats; object-key order and intent wording
do not create a new effect. Node reuses the original COMPLETE or ERROR receipt
and does not dispatch a duplicate RPC. Host also rejects replay/new-envelope
attempts from an already-used source or cached tool key. A repeated action
consumes a model turn but not a new tool attempt. The final model turn cannot
dispatch a tool, even for a would-be cache hit.

Next-turn history and observations must exactly match Host-held records.
Recomputing a context or observation hash does not authorize replacing the
underlying material. Task, scope and obligations stay equal to the initial
recorded context; system text stays equal to the first request. Comparisons
preserve JSON types, so True cannot substitute for integer 1. Context identity
is SHA256 of the exact compact serialized message array. Both the complete
context and its enclosing wire frame must fit; no input is silently trimmed.

The final candidate must match the latest actual COMPLETE final action with
complete=true and no unresolved items. Host independently reconciles request
identity, candidate text, context hash, status and counters. Tool completion
and an input-specific audit are observations, not proof of the original problem.
Public results contain only the designated candidate/unsolved text, fixed
labels/reasons and counts. Full contexts, tool material and raw exceptions
are not returned in the public result.

## Time, responsibility and failure

Python's root monotonic deadline starts at run entry and includes validation,
startup, handshake and tool work. Node can only tighten its remaining-time
view. The effect adapter now accepts a trusted absolute root_deadline and takes
the minimum of it and the per-effect window, preserving the 25 ms reserve.
It cannot create a fresh five-second budget for each effect.

Host model/effect records distinguish ADMITTED, DISPATCHED and returned or
unknown outcomes. A thrown or invalid effect receipt becomes UNKNOWN and
stops without a retry. Late COMPLETE outcomes do not become reusable
observations or candidates; UNKNOWN remains UNKNOWN even after expiry.
Cleanup uses the inherited separate bounded child-reaping step and closes
pipes/selectors. These are in-memory local responsibility records, not a
durable external-service ledger or a promise of remote cancellation.

| Normal synthetic path | Model callbacks | Tool executions | Total frames |
| --- | ---: | ---: | ---: |
| Zero model budget | 0 | 0 | 6 |
| Direct final | 1 | 0 | 8 |
| Tool then final | 2 | 1 | 12 |
| Tool, duplicate, final | 3 | 1 | 14 |
| Two distinct tools, final | 3 | 2 | 16 |

These are observed successful-path counts, not a requirement to spend the
entire budget. Parse errors, unavailable capabilities, unknown outcomes,
oversized contexts and time limits can stop earlier.

## Verification and remaining work

Supervisor verification on 2026-10-11: build and 92 Node tests passed (86 prior
plus 6 groups); 347 Python tests passed (288 prior plus 59), with the same
24 optional WASI skips. The new Python suite executes the actual isolated
operators for positive controls, disables network and old solver entry points,
and checks children, pipes and selectors on success and failure.

Live interception tests alter requests/results while the real Node session
is running, rather than replaying against an already-closed Host. They cover
tool arguments, source and scope, duplicate dispatch, candidate fabrication,
type-preserving context reconciliation, unknown/late outcomes and malformed
protocol. A large-Unicode context plus repeated large observation fixture
stops before the third model request without truncation. A forged closeout
hash is rejected without committing the pending cache accounting update.

Additional supervisor probes independently rejected twelve live mutations:
four tool request changes, six rehashed context changes and two fabricated
candidates from non-final/incomplete replies. Direct CLI checks observed the
frame counts above. These are synthetic engineering checks, not a real model
or competition accuracy evaluation.

Implementation and tests were drafted by the assigned dsh DeepSeek executor,
then independently reviewed, applied and tested. Truncated/invented tests and
a misplaced cache-update patch were withheld or repaired; no new test
dependency was installed and no acceptance assertion was removed to obtain
a pass. Host method loading, formal client adaptation, durable external
request responsibility, full M2/M4/M5 policy, complete a2 parity and target
deployment acceptance remain unfinished.
