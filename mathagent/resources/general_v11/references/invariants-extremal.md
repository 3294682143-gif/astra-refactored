# 不变量、势函数与极端原理

## 可观察产物

确定候选不变量/势函数，并检验所有合法操作；区分障碍与可达构造。 若本次没有推进这一步，记录“未观察到具体增益”，不按读取次数计有效。

## 成立条件

状态、合法操作和目标明确；不变量应在所有合法操作下保持，而非只在几次试验中保持。

## 方法

1. 寻找模值、染色、奇偶、总和、秩或连通信息等粗不变量。
2. 若需证明终止，找有下界的离散严格下降势函数，或给出更精细的良基序；实数势函数仅严格下降不保证有限终止。
3. 对存在/极值题选一个极端对象，证明局部改进或交换与其极端性冲突。
4. 不变量相同只排除了一个障碍，通常不证明可达；需要明确构造或充分性。
5. 博弈策略需覆盖对手每个合法回应，不能只验证一条自选路径。

## 产出与失败信号

输出操作保持性证明、障碍或终止界；构造与界分开。发现合法操作破坏候选不变量时修订该量，不忽略此操作。

## 验证

小规模全枚举可检查映射或发现反例；从有限规模到任意规模的桥梁须单独证明。

## 正例与误用负例

正例：操作总改变整数和的偶数倍时，总和奇偶是可达性的必要条件。
负例：势函数每步减半且为正，并不能保证过程有限步到零。

## 绑定计算工具与精确调用契约 (Bound Registered Tools)

本节只列当前 P3 协议白名单（11 个注册算子）里本卡真正可调用的注册工具。工具只对显式输入重算一次精确结果并给独立校验，不判定“题目→输入”的映射是否正确，也不替代原题的证明义务。

### `bounded_enumeration`
- 何时用：在有限状态空间里穷举，检验候选不变量是否被所有合法操作保持，或找出破坏它的反例。
- `args` 模板：
```json
{"objects":[[0,0],[1,3],[2,6]],"choose":2,"predicate":"sum(1)==3*sum(0)"}
{"ranges":[3,2],"choose":2,"predicate":"sum(0)>=sum(1)"}
```
- 输入约束：`objects` 与 `ranges` 只能给一个；`choose` 取 1..6；对象 ≤ 60 行、每行 1..4 个 int/str 属性（同元数），`ranges` 为 1..4 个 1..60 的维度；组合总数 ≤ 5,000,000；`predicate` ≤ 400 字符，只能使用 distinct(i)/count(i,v)/size()/sum(i)/min(i)/max(i)/contains(i,v) 加算术比较与 and/or/not（索引从 0 开始）
- 输出边界：枚举只认证这个显式宇宙与谓词，不替你证明“题目对象 ↔ 属性表”的映射；小规模穷举不是无限族的证明。
