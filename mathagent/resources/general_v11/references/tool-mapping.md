# 工具正确之前，先明确它在算什么

固定工具收到正确参数可能精确计算一个错误的模型。输入/候选/回执哈希只能确认身份，不能证明编码忠实于原题。

## 每次关键调用的最小记录

1. **子问题**：此调用计算哪个量，输出类型是什么？
2. **对应**：变量、状态、参数、样本空间、单位怎样对应原题？为相关原题约束逐项记录 encoded、by_reduction、deferred 或 irrelevant；不能漏项。
3. **范围**：计算域是否覆盖原题全部情况？是否有逆映射、遗漏、重复、权重、端点或退化分支？
4. **剩余义务**：计算后哪些结论还需解析证明、独立审查、误差界或另一个子问题？

探索计算可以在对应关系未完全证明时进行，但其结果只属于子问题，不能被提升为原题已解。

## binary_strings 的典型错配

该工具的固定模型只含：二进制、指定长度、不相邻1、1的数量同余。它没有首位、末位、字典序、权重等额外参数。

若原题还规定首尾为0，直接输入原长度会漏条件。可以证明删去两个固定零与中间串之间的双射，解释不相邻条件和1的数量为何保持，再对中间长度调用。原长度、工具长度与删补操作的对应必须写清。

若首尾换成1，边界对内部的约束和1的数量偏移也会变化；不能沿用上一种缩短操作而不重新证明。

无论工具是否返回 pass，对漏掉的首尾条件必须保留未完成状态。将“末位为0”贴上现有工具没有实现的 feature 名称也不能算编码完成。

## 计算范围与结论范围分离

- 求一个候选根并代回，不证明找全所有根。
- 在指定有限域枚举，不证明无限域的全称命题。
- 检验导数/方程残差，不证明积分收敛、PDE边界条件或解的唯一性。
- 统计公式计算正确，不证明独立性、抽样模型或因果识别假设。
- 形式化内核通过一个编码命题，还需检查编码是否忠实于原题。

## 宿主辅助检查的边界

reasoning_contracts.assess_mapping 对六个固定工具检查请求身份、约束覆盖、声明的编码特征与独立审查记录。对完整等价模型才允许批准“将该计算用于原目标”；必要条件、诊断或部分子问题保留 unknown。

宿主应先独立审核原题约束清单，再审核正反映射、重数和域覆盖。审查记录必须由宿主实际登记，不能把模型自填的 pass 或 original_mapping_checked=true 原样当可信凭证。

代码能拒绝缺项、明显不支持的参数/特征或错绑定，但不能自动证明自然语言对应关系。微积分、拓扑、统计等没有可用计算适配器时，分别进行相关数学审查，不因“无工具”判错，也不从这六个工具测试推断那些领域正确。

## v1.1宿主记录要点

- profile：problem_id、original、goal、constraints（id/statement/origin/source_quote或依据）、ambiguities。
- mapping：problem_id、candidate_id、candidate_sha256、完整request、computed_subproblem、target_scope、relation、forward_map、reverse_map、multiplicity、covers_all_cases、constraint_coverage、remaining_obligations及两个实际审查引用。
- 工具回执还绑定 tool_request_sha256 和 mapping_ref；映射审查同时绑定候选内容、画像、映射和请求。改变答案或解释后必须作为新内容重新审核，不能仅复用candidate_id。
- candidate_sha256绑定交付对象除solution_status、checks、open_obligations外的所有字段，避免新增数学说明逃逸绑定；运行时费用/时间等可变遥测应另存，不附入已冻结候选。
- profiles/mappings/reviews必须由宿主管理。先做探索计算的记录可不完整，但只能得到unknown的原题映射状态；这不禁止计算本身。

这些散列用于当前记录的关联与防错用，不是题库白名单，更不是数学真值证书。
