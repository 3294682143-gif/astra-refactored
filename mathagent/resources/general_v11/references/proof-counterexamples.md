# 量词、证明义务与反例

## 可观察产物

给出满足全部前提的见证/反例，或列出可逐项审核的量词与证明义务。 若本次没有推进这一步，记录“未观察到具体增益”，不按读取次数计有效。

## 成立条件

把命题的论域、量词与蕴含方向写清。存在、任意、唯一、必要、充分要求不同的证据。

## 方法

1. 将结论拆为可审查的子命题，保留依赖；充分性和必要性分别处理。
2. 构造存在性见证时核验它满足全部前提。唯一性需比较任意两个可能对象。
3. 推翻全称命题，找一个满足前提、违反结论的例子；优先边界、退化、小维数和非独立/不连续等被忽略情况。
4. 反证法先正确否定目标，再找与已知前提冲突的陈述，不把“很不合理”当矛盾。
5. 引用定理要核对条件与量词；结论未知就保留缺口，不杜撰定理。

## 产出与失败信号

给出见证/反例、前提核验和关键逻辑链。只得到许多正例、一个模型赞同或同结论的另一段文字，都不补全证明。

## 验证

独立检查依赖图是否循环、是否把结论当引理、是否交换了“对每个x存在y”和“存在y对每个x”。

## 正例与误用负例

正例：反驳“有界实数列必收敛”，用两个分离值交替并核验有界性及不收敛。
负例：为反驳关于连续函数的断言，拿一个不连续函数作反例。

## 绑定计算工具与精确调用契约 (Bound Registered Tools)

本节只列当前 P3 协议白名单（11 个注册算子）里本卡真正可调用的注册工具。工具只对显式输入重算一次精确结果并给独立校验，不判定“题目→输入”的映射是否正确，也不替代原题的证明义务。

### `bounded_enumeration`
- 何时用：在全称命题的有限模型里搜索满足全部前提却违反结论的反例。
- `args` 模板：
```json
{"objects":[[1,1],[2,4],[3,9]],"choose":2,"predicate":"sum(1)!=sum(0)*sum(0)"}
{"ranges":[4,4],"choose":2,"predicate":"min(1)<max(0)"}
```
- 输入约束：`objects` 与 `ranges` 只能给一个；`choose` 取 1..6；对象 ≤ 60 行、每行 1..4 个 int/str 属性（同元数），`ranges` 为 1..4 个 1..60 的维度；组合总数 ≤ 5,000,000；`predicate` ≤ 400 字符，只能使用 distinct(i)/count(i,v)/size()/sum(i)/min(i)/max(i)/contains(i,v) 加算术比较与 and/or/not（索引从 0 开始）
- 输出边界：枚举只认证这个显式宇宙与谓词，不替你证明“题目对象 ↔ 属性表”的映射；小规模穷举不是无限族的证明。
